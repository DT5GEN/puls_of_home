# История разработки и решений

Дата выгрузки: 2026-10-21. Источник: обсуждение с Claude в чате (проект «Пульс Дома»). Файл нужен, чтобы любой новый сеанс Claude Code или другой аккаунт мог восстановить контекст и при желании свернуть в сторону от принятых решений.

## 0. Как продолжить в новой сессии

1. Прочитай `CLAUDE.md`, `docs/TZ_dom_status.md` и этот файл.
2. Этап 1 (модель данных, переходы, видимость, тесты) **ещё не начат**: код приложения не написан. Первый шаг: `docs/prompts/01_model_and_tests.md`. Сначала попроси план без изменений, потом реализацию.
3. Схема дома генерируется командой `python3 tools/gen_dom_draft.py` (результат: `docs/dom_draft.json`).
4. 3D-референс: `docs/prototype/house3d_g_shape.html`. Откройте файл в браузере (three.js подгружается с cdnjs). Это только референс интерфейса.
5. Решения из раздела «Открытые вопросы» принимает владелец, не агент.
6. Чтобы изменить принятое решение, создай ветку `docs/<тема>`, поправь ТЗ и добавь запись в раздел 7 этого файла с датой и причиной.

## 1. Контекст и мотивация

- У жильцов есть система заявок управляющей компании (УК) по схеме «один на один». Жилец не видит, есть ли такая же проблема у соседей, в других подъездах, как она решается. Статуса «по дому» нет.
- Идея: общий видимый статус дома на 3D-модели. Цвет окна квартиры отражает состояние (зелёный, жёлтый, красный, серый). Под моделью чат дома, заявки, архив решённых задач по категориям («как решали такую проблему у соседей»).
- Цели: взаимопомощь, координация, прозрачность. Для УК это возможность показать, что работа ведётся.
- Масштабирование (позже, возможно командой): дом, группа домов, квартал, район. На соседние дома жилец смотрит как наблюдатель: видит статусы и решения, пишет в чат, но заявок на чужой дом не создаёт.
- Ранний прототип с другим ИИ-ассистентом был примитивным (два подъезда, шесть этажей, табло статусов). Теперь цель: более продуманный MVP, который можно «пощупать».
- Финансирование: бесплатная работа в долгую нецелесообразна. Решено: никакой рекламы и премиум-функций. Допустима добровольная поддержка (QR/СБП). Возможны лицензия для организаций или продажа.

## 2. Принятые решения (по порядку обсуждения)

### 2.1 Осуществимость и архитектура
- Реализуемо как PWA: React и Three.js, роли, чаты, заявки как конечный автомат. Claude Code справляется при работе этапами с чётким ТЗ.
- Трудности не в коде: привязка окон к реальным квартирам, верификация жильцов, правила модераторов, интеграция с УК, градация срочности, персональные данные.
- Порядок этапов: прототип на моках, бэкенд заявок с тестами, чат и real-time, вход и модераторы, архив и фото, пилот на одном доме, группа домов.

### 2.2 Приватность и вход
- Персональные данные не хранятся: ни ФИО, ни email, ни телефона (если нужен для восстановления, то хеш). Пользователь выступает как «место» в квартире с псевдонимом.
- Вход по приглашению: код от УК или уже подтверждённого соседа. Сервер хранит только связку «анонимный токен, квартира».
- Не больше 1–2 мест на квартиру (`dostup_mest`, по умолчанию 2). Лимит проверяется в базе.
- Верификация обязательна и для наблюдателей. Публичного доступа без входа нет.
- Псевдонимы: свободный ввод или выбор из списка. Узнаваемых персонажей мультфильмов не использовать (права). Подойдут нейтральные имена вроде «Сосед 14».
- Номер квартиры в доме почти равен адресу, поэтому «нет имён» не равно «нет данных»: описание и фото внутри квартиры по умолчанию видны только модератору и жильцам квартиры.

### 2.3 Модель дома
- Реальный дом: 10 этажей, 3 секции (подъезда), по данным 209 квартир. Первые две секции мельче по метражу, в третьей есть трёхкомнатные.
- Оценка квартир на этаж: секция 1: 8, секция 2: 7, секция 3: 6. Итого 21 на этаж, 210 на дом. Расхождение с 209 на единицу не выяснено. Пока везде одинаково, квартира 210 помечена неактивной (`aktivna: false`: серое окно, заявки нельзя, в статистике не участвует).
- Планировка: точных данных пока нет. Ориентир: план типового этажа соседнего корпуса того же комплекса (три секции, у каждой узел с лестницей и лифтом, два крыла). Номера квартир и площади на нём не читались, поэтому берём структуру, а не цифры.
- Секции в форме: подъезды 1 и 2 стоят в линию, подъезд 3 под 90°, дом в плане буквой Г. Входы в подъезды со стороны двора.
- Иерархия: квартал, группа домов, дом, секция, этаж, квартира, окно.
- Идентификатор объекта: uuid в базе плюс читаемый `kod` формата `индекс-насел.пункт-улица-дом-секция-этаж-квартира-окно`. Связи только по uuid.
- Четыре уровня объектов: территория (двор, парковка, шлагбаум, подвал, бомбоубежище, площадки, освещение, полив, беседка, урны, лавочки, газоны), секция (входная группа, тамбур, лифт, лестница, окна и двери подъезда), этаж (коридор), квартира. Лифт общий для секции. Бомбоубежище одно на несколько домов, привязано к группе домов.
- Каждой квартире на старте по одному окну-заглушке. Угловые и двусторонние квартиры получат больше окон позже, id окон это учитывает.

### 2.4 Типы обращений и видимость
- Три типа: заявка (что-то сломано), замечание (что-то не устраивает), предложение (что улучшить). У каждого свой цикл. Предложения окно не окрашивают и показываются отдельным списком.
- Авария (красный): описание видно всем, скрыть нельзя, комментарии открыты, соседи секции получают уведомление. Понизить до замечания может только модератор. Причина: авария может угрожать соседям, и соседи могут помочь.
- Замечание (жёлтый): по умолчанию видно описание. Автор может выбрать режим «только цвет». Комментарии открыты, чтобы соседи могли спросить и помочь.
- Замки и двери: цвет виден всем, описание только модератору и жильцам квартиры (чтобы не выдавать, что квартира пустует).
- Зелёный вычисляется автоматически, когда все заявки квартиры закрыты и подтверждены.
- Интерфейс наблюдателя: одна строка «КВ-45» и короткое описание мелким шрифтом, по нажатию раскрываются дата, статус, комментарии. Интерфейс жильца: свои заявки сразу развёрнуты на главном экране с кнопками «подтвердить» и «изменить».

### 2.5 Подтверждение закрытия (версия 2) и даты
- Квартира: УК или автор ставит серую отметку «сделано», закрыть может только житель квартиры. Модератор в квартиру не ходит.
- Общая зона секции и двор: серая отметка, затем подтверждение модератора другой секции этого дома (диверсификация проверяющих). Пока таких модераторов нет, подтверждает верифицированный житель другой секции.
- Предложение: подтверждает автор.
- Подтверждающий не может быть автором, не может подтверждать общую зону своей секции, даёт одно подтверждение на заявку.
- При подтверждении житель выбирает дату: «по отметке УК» или «фактически сегодня». Сохраняются обе (`claimedDoneAt`, `actualDoneAt`), статистика считается по фактической.
- Модераторы подъезда назначаются голосованием жильцов секции, а не админом.

### 2.6 Эскалация, УК, метрики
- Если УК не ответила на аварию за 24 часа (параметр), модератор получает уведомление.
- Дашборд для УК показывает те же данные, что видят жильцы, плюс ответ и статус «в работе». Закрытого списка, которого не видят жильцы, нет.
- Публично только факты: даты, статусы, количество заявок, без оценок и без имён жильцов. У УК есть право ответа.
- Метрики для будущей статистики по домам: медианное время до первого ответа УК, доля заявок, подтверждённых с первого раза, доля переоткрытых. Не публиковать рейтинг дома, пока заявок меньше 10.

### 2.7 Идеи на потом (не этап 1)
- День и ночь по местному времени и закату (расчёт положения солнца по координатам дома). Ночью здание темнеет, окна светятся цветом статуса.
- Погода по координатам дома через API (Open-Meteo, OpenWeatherMap и т. п., условия использования проверить). По умолчанию включена, пользователь может отключить.
- «Живой двор»: стилизованные случайные силуэты и редкие машины. Движение случайное и не связано с реальными жильцами (чтобы не было слежки). По умолчанию включено, переключатель отключения, для слабых телефонов выключать.
- Раздел с мастерами по категориям: рейтинг по отзывам жильцов. Платные позиции в рейтинге недопустимы. Если когда-нибудь появится реклама, то отдельным помеченным блоком (38-ФЗ), решать после пилота и с юристом.

### 2.8 Монетизация, название, право
- Без рекламы и premium. Добровольные донаты через СБП или QR, налоговый режим уточнить у бухгалтера. Публиковать, на что тратятся деньги.
- Название «Пульс дома»: слово «Пульс» занято приложениями для измерения пульса. Проверить реестр ФИПС (классы 9, 42, 45, возможно 35), RuStore, App Store, Google Play, домены.
- Модели использования: (1) закрытый код с лицензией для организаций без роялти, (2) открытый код под AGPL, (3) MIT/Apache. Выбор ещё не сделан. Подробно в `docs/TZ_dom_status.md`, раздел 13.
- Заложено в архитектуру: бренд и тексты только из конфигурации, поле `tenantId`, проверка лицензий зависимостей (`LICENSES.md`), экспорт и импорт схемы дома.
- Список вопросов юристу: `docs/legal_questions.md`.

### 2.9 Эволюция 3D-прототипа
1. Плоский фасад из трёх секций SVG: время суток, погода, силуэты, карточка заявки с выбором даты.
2. Три блока в ряд в Three.js: вращение перетаскиванием, нажатие на окно, роли «наблюдатель» и «житель».
3. Правки владельца: машины в 4–5 раз реже, местное время по умолчанию, погода и «живой двор» включены по умолчанию.
4. Форма Г: секции 1 и 2 в линию, секция 3 под 90°, входы со стороны двора, окна по всему периметру, туман ослаблен. Между секциями 2 и 3 добавлен глухой угловой блок (допущение, подтвердить по реальному плану).

## 3. Инструменты и процесс

- Чат Claude: планирование, ТЗ, промпты, разбор PR. Claude Code в терминале WebStorm или VS Code: реализация, Docker, тесты, ветки и PR.
- Работа по задачам: одна задача, одна ветка, один PR. Тесты владелец запускает локально. `main` защищён, слияние только через PR.
- На старте нужны только коннектор GitHub, `CLAUDE.md` и список разрешённых команд Claude Code. Сторонние коннекторы без проверенного происхождения не подключать. Скиллы пока не нужны.
- Лимиты подписки Pro у владельца закончились до 23 октября 2026, поэтому Claude Code до этой даты недоступен.
- Коннектор GitHub (Custom) в чате видит публичные репозитории, но не приватные, и не имеет прав записи (ответ 403 при попытке записи). Поэтому документы выгружаются вручную из архива. Для работы ассистента через чат нужен токен с правами на чтение и запись Contents и Pull requests.
- Репозиторий временно был сделан публичным, чтобы коннектор его видел. После выгрузки вернуть приватность (в файлах есть название улицы и упоминание комплекса).

## 6. Известные риски и вопросы

- GPL v3 в репозитории против плана «закрытый код с лицензией для организаций»: GPL v3 не покрывает запуск как сетевой сервис (для этого AGPL), копилефт распространяется на производные работы. Вопрос к юристу.
- Права на код, написанный с помощью Claude Code: сверить с официальными условиями Anthropic и с юристом.
- Публичность описаний аварий: польза соседям против риска показать пустующую квартиру.
- Публикация сроков и рейтинга УК: формулировки только фактические, возможен иск о клевете.
